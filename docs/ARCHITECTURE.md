# Архитектура проекта «Финни»

Документ объясняет, как устроен весь проект: из чего он состоит, как
данные движутся по приложению, где что лежит, как собрать и развернуть
и как добавлять новое. Читать сверху вниз: сначала общая картина, потом
детали мобильного приложения, потом сервер, развёртывание, тесты и CI.
Игровые механики и их смысл для обучения — в
[GAME_DESIGN.md](GAME_DESIGN.md).

---

## 1. Общая картина

«Финни» — детская игра (7–10+ лет) для Android: ребёнок заботится
о питомце, решает задания по математике и финансам, тратит и копит
монетки. Цель — научить обращаться с деньгами: «надо» и «хочу», бюджет,
копилка, цели.

Репозиторий — монорепо из двух независимых частей:

```text
LCT.hack/
├── mobile/     Flutter-приложение (Android). Вся игра — здесь.
├── backend/    FastAPI-сервер: справочники и резервная копия прогресса.
├── design/     Готовые ассеты для публикации (иконка 512 для RuStore).
├── docs/       ARCHITECTURE.md (этот документ), GAME_DESIGN.md, SPEC.md.
└── .github/    CI: отдельный пайплайн для mobile и для backend.
```

**Главный принцип: игра полностью офлайн.** ТЗ требует, чтобы игровой
цикл работал без сети и прогресс не терялся. Поэтому весь контент
(задания, товары, цели, скины) зашит в приложение, а состояние хранится
на телефоне. Сейчас мобильное приложение к серверу **не обращается** —
сервер готов как задел (раздача справочников и резервная копия
прогресса), но в игровом цикле не участвует.

```text
┌──────────────────────── Телефон ────────────────────────┐
│                                                          │
│   Экраны (screens/)  ──читают/вызывают──►  GameState     │
│        ▲                                   (models/)     │
│        │ перерисовка (ChangeNotifier)         │          │
│        └──────────────────────────────────────┤          │
│                                               ▼          │
│   Каталоги (data/)  ◄──константы──  SharedPreferences    │
│   задания, товары,                  (JSON-сейв)          │
│   цели, скины                                            │
└──────────────────────────────────────────────────────────┘
            ┆ (не используется сейчас, задел)
            ▼
┌──────────── Сервер (backend/) ────────────┐
│ FastAPI: /content/* — справочники (JSON)  │
│          /progress/* — снимок профиля     │
│ SQLite локально / Postgres в Docker       │
└───────────────────────────────────────────┘
```

## 2. Мобильное приложение (`mobile/`)

### 2.1. Стек

- **Flutter / Dart** (stable 3.44+, Dart 3), одна платформа — Android 8.0+,
  портрет, от 360dp. Material 3, светлая и тёмная тема.
- Зависимости минимальные: `shared_preferences` (сейв) — и всё. Нет
  Provider/Bloc/Riverpod, нет HTTP-клиента, нет пакетов анимаций:
  меньше APK, быстрее старт (ТЗ: запуск до 5 с). Разрешений Android
  приложение не запрашивает.
- Все анимации и эффекты («огонёк», дорога заданий, прыжки питомца)
  нарисованы кодом: `AnimationController` + `CustomPainter`.

### 2.3. Состояние: один `GameState`

Всё состояние игры — один объект `GameState extends ChangeNotifier`
(`models/game_state.dart`):

| Группа | Поля |
|---|---|
| Профиль | `profile` (ник, возраст), `onboardingDone` |
| Питомец | `pet` (вид, окраска, сытость/счастье/чистота, XP, уровень), `skinId`, `ownedSkins` |
| Деньги | `balance` (кошелёк), `savings` (копилка), `goalName/goalEmoji/goalTarget` |
| Время | `day` (игровой день), `lastBonusDate` |
| Задания | `lessonsSolved`, `lessonsRetry` («Повтори»), `lessonMistakes` |
| Инвентарь | `inventory` (id товара → количество) |
| Огонёк | `streak`, `lastActionDate`, `actionPulse` |
| Настройки | `isDark` |

**Как экраны получают состояние.** Вместо Provider — свой
`GameStateScope` (`app.dart`), это `InheritedNotifier`:

- `GameStateScope.of(context)` — в `build`: виджет подписывается и
  перерисуется при любом изменении.
- `GameStateScope.read(context)` — в обработчиках нажатий: без подписки.

**Как меняется состояние.** Экран никогда не меняет поля напрямую, он
вызывает метод: `buyItem`, `deposit`, `answerLesson`, `nextDay`,
`buySkin`… Каждый метод:

1. проверяет правило (хватает ли монет, не отрицательный ли баланс);
2. меняет поля;
3. если это полезное действие — `_registerAction()` (огонёк);
4. `notifyListeners()` → все подписанные экраны перерисовываются;
5. `save()` → сейв на диск.

Так все правила ТЗ живут в одном месте, и их не обойти из UI:
отрицательный баланс невозможен, награда за задание начисляется один раз,
ошибка не отнимает прогресс.

### 2.4. Сохранение

`GameState.save()` сериализует всё в один JSON и кладёт в
`SharedPreferences` под ключом `finny_state_v1`. `load()` читает его
на старте.

Загрузка написана **терпимо к старым и битым сейвам**: каждое поле
читается с запасным значением, неизвестные id заданий и скинов
отбрасываются, возраст «11» из старых версий превращается в «10+».
Ошибка чтения не роняет приложение — игра просто начнётся заново.
Поэтому новые поля можно добавлять без миграций.

Не сохраняются (живут до перезапуска): `pendingLevelUp`, `actionPulse`,
`pendingBonus`, `justFinishedOnboarding` — это одноразовые события
для экрана.

### 2.5. Игровой цикл и экономика

```text
 новый день ──► +доход (40 + уровень×10) ──► статы питомца падают
     ▲                                             │
     │                                             ▼
 «бумажка»        ребёнок: кормит (рюкзак), покупает (магазин),
 с итогами        копит (копилка), решает задания (дороги)
     ▲                                             │
     └──────── опыт ──► 100 XP = новый уровень ◄───┘
                        (+25 монет, статы 100, доход растёт)
```

- **Опыт** дают: предметы из рюкзака, пополнение копилки, решённые
  задания. `_addXp` сам поднимает уровень и кладёт событие в
  `pendingLevelUp`; экран роста показывает `showLevelUpIfNeeded()`.
- **Этапы питомца:** уровень 1 — Малыш, 2 — Подросток, 3+ — Взрослый.
- **Ежедневный бонус** +15 за возвращение в новый календарный день —
  плашкой на главной (`claimDailyBonusIfNeeded`, `pendingBonus`).
- **Итоги дня:** `nextDay()` возвращает `DaySummary` — доход и
  *реальную* просадку статов (если сытость была 10, в итогах будет −10,
  а не −15). Из него `showDayPaper` собирает «бумажку».
- **Настроение** (`Pet.mood`) считается из статов: грусть при ≤20,
  дальше голод → грязь → скука, при всех ≥75 — радость. Оно даёт
  фразу, мордочку и анимацию модели.

Все числа — константы в начале `game_state.dart` и в каталогах `data/`.

### 2.6. Задания: две дороги

`data/lessons_data.dart` — каталог `Lesson`: дорога (`math`/`finance`),
класс (1–4), вопрос, 4 варианта, номер верного, разбор и справка.

- **Каталог:** 35 заданий — «Математика» 4 класса по 5, «Финансы»
  3 раздела по 5 («Азбука финансов», «Мастер накоплений», «Вклад в
  будущее»).
- **Рекомендация по возрасту:** `recommendedGrade(age, track)` — 7 лет →
  1 класс, 8 → 2, 9 → 3, 10+ → 4 (или последний класс дороги).
  Раздел подсвечен «⭐ Твой уровень», но **открыты все задания**.
- **Ответ:** `GameState.answerLesson(id, choice)`:
  - верно в первый раз → монеты (`5 + класс×10`) и 10 XP;
  - повторное верное решение → без награды;
  - ошибка → ничего не отнимаем, задание попадает в `lessonsRetry` —
    временную задачу «Повтори» (правило ТЗ: провал создаёт временную
    задачу, а не сбрасывает прогресс).
- **Следующее задание** (`nextLesson`) на главной: сначала «Повтори»,
  потом нерешённое своего класса, потом любое.
- **Экран дороги** (`quests_screen.dart`): кружки идут змейкой по
  синусоиде, дорогу рисует `_RoadPainter` (кривые Безье + пунктир),
  пройденные участки закрашиваются цветом дороги.

Новое задание = новая запись в каталоге. Код не меняется.

### 2.7. План, магазин, скины, копилка

- **План** (`plan_screen.dart`): три шага «Сначала важное → Потом
  интересное → На мечту» с живыми цифрами (кошелёк, предметы в рюкзаке,
  копилка/цель) и кнопка «Отложить 20 в копилку».

- **Товары** (`shop_data.dart`): 26 товаров, 6 отделов. «Надо» (еда, уход, здоровье)
  и «Хочу» (игры, наряды, уют) — `ItemKind.mandatory`. Купленное падает
  в `inventory` и тратится в рюкзаке (эффект на статы + XP).
- **Скидка дня:** `dealOfDay(day)` выбирает товар по номеру дня,
  `GameState.priceOf(item)` возвращает цену со скидкой 30 %.
- **Скины** (`skins_data.dart`): по 3 на вид питомца. Покупаются один
  раз навсегда (`ownedSkins`), надеваются/снимаются (`skinId`).
  Показываются только скины текущего вида.
- **Копилка** (`bank/`): пополнение кнопками +10 / +25 / +50 (не больше,
  чем в кошельке), каждое пополнение даёт 5 XP. Цель — одна из 6 готовых
  (`goals_data.dart`) или своя (название, эмодзи, 50–5000); накопленное
  при смене цели сохраняется. Снятие — только через диалог
  подтверждения, который заранее показывает новую сумму и новый срок до
  цели (срок считается из 25 монет в день, `daysToGoal`).

### 2.8. Питомец: модели и эмоции

Модели питомца будут **анимированными WebP**. Система уже готова:

```text
assets/pets/<вид>/<образ>/<анимация>[_<этап>].webp
  вид:      cat | dog | penguin
  образ:    v1 | v2 | v3 (окраска) или id скина
  анимация: idle | happy | eat | sad | sleep
  этап:     baby | teen | adult (необязательно)
```

Как это работает:

1. На старте `PetAssets.init()` читает `AssetManifest` и запоминает,
   какие файлы моделей реально есть в APK.
2. `PetModel` (виджет) спрашивает `PetAssets.resolve(...)` — какой файл
   показать для текущей анимации. Порядок поиска:
   `анимация_этап` → `анимация` → `idle_этап` → `idle` → **заглушка**.
3. Есть файл — `Image.asset` проигрывает WebP-анимацию. Нет файла —
   рисуется заглушка (цветной круг окраски/скина + эмодзи).
4. Поверх модели `PetModel` рисует эмоции кодом: «дыхание» в покое,
   покачивание при грусти, прыжок с тенью и значком реакции
   (💛/😋/💤) на действие.

Реакцию запускает счётчик `reaction`: главный экран увеличивает его
после рюкзака (еда → `eat`, остальное → `happy`) и после нового дня
(`sleep`).

Художнику достаточно положить файлы в нужную папку — подробная памятка
в `mobile/assets/pets/README.md`. Папки уже созданы и объявлены в
`pubspec.yaml`.

### 2.9. «Огонёк»

Два уровня отклика на действие:

- **`SparkOnAction`** — короткая вспышка (700 мс) рядом с тем, что
  сделали: на купленном товаре, на копилке, на питомце. Запускается
  увеличением счётчика `trigger`.
- **`StreakFlame`** — 🔥 в шапке. Число — сколько календарных дней
  подряд ребёнок делал хоть одно полезное действие (`streak`). Каждое
  действие увеличивает `actionPulse`, и огонёк в шапке вспыхивает — так
  любое действие в любом месте приложения получает отклик. Если сегодня
  действий ещё не было, огонёк бледный.

Действия, которые зажигают огонёк: использование предмета, покупка
товара или скина, пополнение копилки, верный ответ на задание.

### 2.10. Защитные механизмы

- **Цензура имён** (`services/name_filter.dart`). Ник и кличка
  проверяются при вводе (кнопка «Далее» неактивна, под полем —
  подсказка) и ещё раз в `createProfile`. Алгоритм:
  1. «скелет» строки: нижний регистр, ё→е, транслит (`sh`→ш, `ya`→я),
     латинские и цифровые двойники (`x`→х, `3`→з, `@`→а), выкинуть всё,
     кроме букв, схлопнуть повторы;
  2. вырезать безобидные слова, внутри которых есть «плохие» сочетания
     (Глеб, Аманда, страх, ребёнок…);
  3. искать запрещённые корни; отдельно — английские слова 18+.
  Списки — константы, пополняются без изменения логики.
- **Родительский режим** (Настройки → Родительский режим). Вход —
  после двух «взрослых» примеров (двузначное × однозначное и вычитание
  трёхзначных с переходом через разряд). Внутри: прогресс, смена
  возраста, сброс заданий, полный сброс игры.
- **Режим разработчика** — скрыт: 7 нажатий на строку «Версия…» внизу
  настроек. Даёт опыт (+10/+50/+1 уровень/+3 уровня), монеты
  (+100/+1000) и статы (все 100 или все 10) — чтобы проверять рост питомца без прокрутки дней.
  Работает через обычные методы `GameState`, поэтому награды и экран
  роста ведут себя как в игре.

### 2.11. Навигация

- `app.dart`: если онбординг не пройден — `OnboardingFlow`, иначе
  `MainShell`.
- `OnboardingFlow`: `PageView` без свайпа, 7 шагов (приветствие → ник →
  возраст → вид → окраска → кличка → правила). Черновик живёт в
  состоянии экрана, в `GameState` сохраняется один раз на финише.
- `MainShell`: `IndexedStack` из 5 вкладок (Питомец, План, Задания,
  Магазин, Банк) — вкладки не пересоздаются при переключении и помнят
  прокрутку. В шапке — огонёк, смена темы, настройки.
- Остальное открывается поверх: `Navigator.push` (задание, настройки,
  родительский режим), `showModalBottomSheet` (рюкзак, цель),
  `showDialog` (бумажка дня, подтверждения).

### 2.12. Требования ТЗ, заложенные в код

| Требование | Где |
|---|---|
| Текст ≥ 16sp | `KidsTheme._textTheme` поднимает мелкие стили |
| Тач-таргеты ≥ 48dp | `minimumSize` у кнопок, `minHeight` у чипов |
| Состояние не только цветом | статы с числом, ✅/❌ иконки у ответов, «Надо/Хочу» текстом |
| Нет отрицательного баланса | проверки в `buyItem`, `deposit`, `buySkin`, `withdraw`; кнопки покупки неактивны, если монет не хватает |
| Подтверждение снятия с копилки | `BankScreen._withdraw` |
| Ошибка → временная задача | `lessonsRetry` |
| Офлайн, прогресс не теряется | весь контент в APK, сейв после каждого действия |
| Нет лишних разрешений и ПДн | `AndroidManifest.xml` без разрешений; в сейве только ник, возраст и игровое состояние, на устройстве |
| Задания начисляют монеты | `answerLesson`: `5 + класс×10` монет и 10 XP |
| Контент без правки логики | каталоги в `data/`, модели по папкам |

## 3. Сервер (`backend/`)

**FastAPI + SQLAlchemy.** По ТЗ сервер не обязателен; поднят как задел.
Запуск, переменные окружения и примеры запросов —
[backend/README.md](../backend/README.md).

```text
backend/app/
├── main.py              Приложение FastAPI, CORS, загрузка контента на старте
├── core/config.py       Настройки из env/.env (БД, путь к контенту, кэш)
├── api/routes/
│   ├── content.py       GET /api/v1/content/* — справочники (ETag, 304)
│   └── progress.py      PUT/GET/DELETE /api/v1/progress/{profile_id}
├── content/
│   ├── library.py       Загрузка и проверка JSON-контента на старте
│   └── data/*.json      catalog, goals, quests, glossary, pets, economy
├── schemas/             Pydantic-схемы (контракт API)
├── services/progress.py Сохранение снимка, конфликт по ревизии
└── db/                  Таблица profile_progress (снимок целиком в JSON)
```

- **Справочники** читаются из JSON при старте; битый JSON или нехватка
  обязательного минимума роняют сервис сразу. Ответы кэшируются по
  ETag.
- **Прогресс**: клиент — источник правды. Сервер хранит последний
  присланный снимок; более старая ревизия отклоняется как конфликт.
  Профиль адресуется UUID, персональных данных нет.
- **БД**: локально SQLite (`finni.db`), в `docker-compose.yml` —
  Postgres 16.
- **API:** справочники — `GET /api/v1/content/manifest`, `/bundle`,
  `/catalog`, `/goals`, `/quests`, `/glossary`, `/pets`, `/economy`
  (и `/{id}` для отдельной записи); прогресс — `PUT/GET/DELETE
  /api/v1/progress/{profile_id}`. Живая документация — Swagger UI на
  `/docs` запущенного сервера; спецификация файлом —
  [backend/openapi.json](../backend/openapi.json) (генерируется
  `scripts/export_openapi.py`).

**Как подключить к приложению (когда понадобится):** добавить `http`,
на старте запросить `/content/manifest`, при изменении версий скачать
разделы и сохранить локально; каталоги в `data/` оставить как
офлайн-фолбэк. Прогресс выгружать тем же JSON, что пишет `GameState.save()`, в
`PUT /progress/{uuid}`.

## 4. Сборка и развёртывание

**Приложение.** Клиент — один APK, сервер ему не нужен:

```bash
cd mobile
flutter pub get
flutter build apk --release   # build/app/outputs/flutter-apk/app-release.apk
```

Готовые APK публикуются в
[GitHub Releases](https://github.com/SilMax-Lang/LCT.hack/releases),
целевой магазин — RuStore (иконка 512×512 — `design/icon/`).

**Сервер** (необязательный) — Docker-образ из `backend/Dockerfile`:

- `docker compose up --build` в `backend/` поднимает API и PostgreSQL 16
  (данные — в volume `db_data`);
- без Compose образ работает на SQLite;
- настройки (строка подключения к БД, путь к контенту) — переменные
  окружения, образец — `backend/.env.example`.

Подробно — [backend/README.md](../backend/README.md).

## 7. Как добавить…

| Что | Куда |
|---|---|
| Задание | запись `Lesson` в `data/lessons_data.dart` |
| Товар | запись `ShopItem` в `data/shop_data.dart` |
| Готовую цель | `GoalPreset` в `data/goals_data.dart` |
| Скин | `PetSkin` в `data/skins_data.dart` + папка `assets/pets/<вид>/<id>/` + строка в `pubspec.yaml` |
| Модель питомца | webp-файл в папку образа (см. `assets/pets/README.md`) |
| Запрещённое слово | `_badRoots` в `services/name_filter.dart` (и тест) |
| Новое поле сейва | поле в `GameState` + строка в `save()` и `load()` с запасным значением |
| Экран | папка в `screens/`, состояние — через `GameStateScope` |
